## 当前证据与缺口

- RELEASE_CRITERIA 的核心能力、评估、工程和面试材料均已有对应 QA/实验路径。
- iter_019 QA 已验证 wheel/sdist 重建、独立环境安装、333 测试、Ruff、CLI 和源码身份。

## 必须完成

1. 重写 `docs/release_audit.md` 为当前 v0.1.0 候选审计：每个 REQ 映射到现有 QA/实验/声明证据，注明适用范围。
2. 明确发布候选已完成本地构建与独立安装验证，但 GitHub 远程发布未发生；禁止写成已发布。
3. 增加一致性测试，拒绝文档继续出现“开发版本/尚不能分发/下一轮需发布 QA”等过期表述，并检查关键证据链接存在。
4. 运行完整 pytest、Ruff、关键 CLI 和发布审计文档回归。

## 明确不做

- 不初始化 Git、不创建远程仓库、不上传外部服务。
- 不修改 `src/`、实验数据、结果注册表或历史 QA 报告。
- 不把本地发布候选等同于 GitHub 已发布，不扩大为全平台或全数据集支持。

## 验收标准

- release_audit 文档不再与 0.1.0 和 iter_019 QA 冲突，并列出未发生的远程发布事实。
- 所有审计链接存在；正式数字只引用 `results/registry.yaml` 的 verified 项。
- 完整 pytest、Ruff、CLI 和至少一个历史失败保留的对抗检查通过。

## 交接
