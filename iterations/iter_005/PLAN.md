# iter_005 计划

状态：已冻结。需求：REQ-006、REQ-007。里程碑：M3。
核心闭环：已观察到的路径枚举 → 前缀内生成参数化循环计划 → 事后检测命令序列匹配。
不实现执行、改写或重放；不声称可以证明 LLM 的未来意图。

## 明确范围与接口

支持源命令 find ROOT -type f -print0，显式 cwd，成功 returncode=0 和完整 raw_output。
以 NUL 分隔列表，至少两个非空、不重复、处于 ROOT 子树中的普通路径。
词法规范化后用于绑定，具有 shell 展开字符等暂不支持的文件名保守拒绝。
为支持该生产者，semantics.py 的 find 增加可选末尾 -print0，原有形式保留。

infer_loop_at(trajectory, start_event_index, cwd_by_call=...) 只读取截至首个消费者调用的前缀，
生成 LoopPlan 或 None。支持单文件 cat/head/tail/wc/sort/uniq 模板，参数来自首调用，
其文件参数必须等于枚举的第一项；其余调用 argv 完全由前缀枚举值展开。
计划含生产者/结果位置、首调用、截止位置、cwd、路径元组、模板前缀、预测 argv、prefix_sha256。
prefix_sha256 不得依赖整个原文件哈希、未来上下文或未来事件；只对可见事件与可见 cwd 编码。
截至首调用仍未完成的更早调用视为屏障；生产者结果后存在未知调用、写入枚举子树或绑定路径则拒绝。
只读或已完成的不相交写入可保留；所有消费者效果须已知只读。

路径生产者选择最近的、符合全部条件且第一项匹配的结果，不混用多个来源。
源列表缺失、不完整/失败、为空/单项、重复、越界、危险语法或 cwd 缺失时拒绝。
调用者的显式 cwd 与原有普通 POSIX 路径模型假设继续适用。

detect_runtime_loops(trajectory, cwd_by_call=...) 在每个起点调用前缀生成器，
只有随后连续 N 个工具调用按同一 cwd、同一模板和同序路径与预测匹配才输出 DetectedLoop。
报告包含 plan、call_ids、event_indices；不能跨越用户/系统新指令或 exit，不能删除中间工具调用。
首调用后的工具输出不参与计划构造；匹配不等于证明观察独立，后续仍须重放。
候选按原序返回且不重叠，缺失后续调用仍可生成计划，但不能称为检测到完整循环。

## 验收

AC-501：双项、多项路径生成正确的冻结计划，并可定位来源与参数绑定。
AC-502：相同前缀、不同未来事件/输出/文件哈希/未来 cwd，生成计划完全相同。
AC-503：生产者晚于消费者、失败/截断/重复/越界列表、未完成或冲突调用均拒绝。
AC-504：完整同序模板匹配接受；顺序变化、缺项、改变常量、插入工具/用户指令拒绝。
AC-505：新增 find -print0 效果符合原模型，全部既有回归通过。
