# 三分钟讲解稿

按约三分钟设计，时间段是排练分配，不是假称已经完成真人计时。正文可直接口述；括号外的证据链接供追问使用。

## 0:00–0:30：问题

TraceOpt 研究工具调用轨迹中能否把重复步骤改写为可执行片段。比如先列出文件，再逐个读取，看起来适合批处理，但仅凭命令相似并不可靠：中间可能改了文件，参数可能来自未来观察，合并结果也可能改变模型后续决策。所以我把重点放在候选的来源、依赖和实际重放证据上。

## 0:30–1:10：表示与依赖

输入是已支持结构的真实 mini-swe-agent 轨迹。解析器把消息、调用和返回转成不可变事件，保留原始位置、调用 ID 和输入哈希。命令语义采用明确白名单，通过显式工作目录提取读写资源，再建立先写后读、先读后写和先写后写依赖。未知命令作为顺序屏障。这里使用词法路径子树模型，不声称解决所有 shell 语义或文件别名。

## 1:10–1:50：绑定与执行

循环计划只使用首个消费者调用时已经可见的信息：成功的 NUL 文件枚举提供路径，首调用提供模板。之后再独立检查轨迹中的完整序列是否匹配。这个检查不证明未来模型意图。执行端目前只支持受限 cat，把原始逐项读取和生成的 Bash 批处理放到相同初始状态上运行，逐项比较输出、返回码、历史记录和仓库快照。

## 1:50–2:30：验证与失败

评估把结构检测和执行成功分开。已验证实验包含四十五个人工案例，同时比较朴素模板基线和去掉依赖屏障的消融。生产检测的十二个 cat 候选都进入重放分母，八个成功、四个失败。一个典型失败是原始与优化输出完全相同，却与轨迹历史不符；另一个是仓库新增文件，使枚举前提失效。这些失败保留在结果中，没有当作跳过。

## 2:30–3:00：结论与边界

当前成果是可追溯的依赖分析、前缀绑定以及受限片段的可执行验证。人工案例上的检测分数不能代表生产分布，固定真实模型轨迹的正例覆盖仍不足，也没有模型端到端成本收益数据。项目用分角色交接、机器状态和 QA 证据保存进展，避免把实现完成误写成验证通过。
