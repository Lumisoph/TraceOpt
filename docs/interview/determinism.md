# 确定性与绑定

## 1. 什么是前缀可见信息？

当前实现指截至首个消费者调用为止的事件，以及这些调用的显式 cwd。infer_loop_at 只切片读取此范围；路径来自更早成功 find 的 raw_output，模板来自首调用。后续调用、输出及上下文都不能参与该计划的构造。
证据：[实现](../../src/traceopt/binding.py)、[前缀读取对抗](../../tests/test_binding_qa.py)。

## 2. 为何不能利用未来观察？

把未来输出用于构造计划，会把离线已知答案伪装成执行当时能做出的决策。当前将前缀构造和离线后缀匹配分开；后者验证轨迹中是否出现完整固定序列，并不证明未来模型一定做相同选择，也不证明观察独立。
证据：[确定性边界](../architecture/determinism.md)、[CLAIM-002](../../CLAIMS.md#claim-002)。

## 3. 运行时绑定和常量复制有何区别？

绑定保存 producer、observation、首消费者位置和前缀哈希，从已观察路径列表生成预测 argv。它不是扫描未来命令后抄出文件名。当前生成的批处理仍使用这次观察得到的固定列表，并非能适应任意新仓库的通用程序。
证据：[LoopPlan 定义](../../src/traceopt/binding.py)、[绑定集成](../../tests/test_binding_integration.py)。

## 4. 如何判定绑定来源？

要求成功的 find ROOT -type f -print0，NUL 完整终止、至少两个唯一根内路径；第一项须匹配首消费者。中间存在影响枚举根/绑定文件的写入、unknown 或新外部指令则拒绝。缺失上下文和未完成的先前调用也不能猜测。
证据：[绑定实现](../../src/traceopt/binding.py)、[挑战集](../../data/challenges/loops_v1.json)。

## 5. 哪些情况应拒绝自动改写？

来源失败或不完整、顺序不符、模板改变、插入调用、用户改变目标、路径别名或片段初始状态不可核验，都不足以放行。结构检测范围比执行器大：head 等可有候选，但当前重放只接受单文件 cat，不能把检测能力当执行能力。
证据：[绑定测试](../../tests/test_binding.py)、[重放实现](../../src/traceopt/replay.py)。

## 6. 如何设计信息泄漏对抗测试？

改变未来输出后要求前缀计划不变，并使用映射对象在读取未来 cwd 时直接失败。另插入用户指令或未完成调用，确认拒绝匹配或推断。测试证明实现的指定读取路径，不是对任何 LLM 或工具程序的普遍确定性证明。
证据：[绑定对抗回归](../../tests/test_binding.py)、[QA 独立测试](../../tests/test_binding_qa.py)。
