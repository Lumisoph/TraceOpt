# 评估

## 摘要

实现位于 src/traceopt/evaluation.py。人工受控挑战集分别衡量结构检测和实际 cat 重放。
iter_008 QA 已验证受控评估管线；正式结果仅引用 results/registry.yaml 的 verified 项。

## 职责与非职责

验证输入标注、执行三种检测方法、按完整调用序列计分、保存实际重放证据。
不自动修改标注、不执行任意轨迹命令、不估算模型成本，也不自动授予 verified。

## 输入与输出

配置 JSON 指定 schema_version、相对配置所在目录的数据路径和超时。
每例含唯一 id、中文 rationale、steps、expected 调用 ID 序列、repository 文本文件映射。
steps 明确给出 command/output/returncode/cwd；也允许用户或系统消息中断。
repository 是候选片段开始前的初始状态，不是整个会话开始状态。

只创建新的输出目录；保存配置和数据副本、manifest、逐例轨迹、初始仓库、预测和重放报告，
最后生成 raw.json 与 summary.json。没有汇总文件表示运行尚未完整结束。

## 算法与计分

生产方法调用 detect_runtime_loops。朴素基线将相邻工具调用中 argv[:-1] 相同的最长序列
作为循环，不要求枚举来源或检查中间消息。单因素消融调用同一私有检测算法，
仅关闭枚举观察与首消费者之间的依赖屏障；其它条件不变。
生产公共接口和重放器始终检查依赖，不能通过公共参数关闭。

计分单位是（案例 ID，完整调用 ID 元组）。跨度完全相等才为 TP；额外为 FP，遗漏为 FN。
逐例集合去重，再微平均求和。P=TP/(TP+FP)，R=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)。
分母为零时对应值为 null，不把空集记为成功。

每个生产 cat 候选实际调用 replay_cat_loop。成功要求其 successful=true。
重放失败、异常、历史不符都进入尝试分母；非 cat 单独计 not_applicable。
重放成功率=successful/attempted，零尝试为 null。错误文本、逐项输出和状态报告保留。

## 不变量与假设

标注在运行前固定；保存数据、配置、全部被测产品代码 SHA-256。
每个成功执行报告保留工具哈希；命令、cwd、环境与时间写 manifest。
严格区分检测正例与执行成功；人工挑战集不能代表生产模型分布或端到端收益。
普通相对文件名经过校验，拒绝越界、Windows 设备/数据流名和文件目录冲突。

## 错误处理

输入无效或输出已存在则报错。无法完成整次评估时不生成完整汇总。
每次重放预期的环境/前提错误记录为该候选失败，不跳过分母。
不吞掉未知程序错误，不把异常视为拒绝候选的成功证据。

## 复杂度

计分为跨度集合操作；总体开销由逐例检测、仓库复制和外部工具重放主导。
受控小型挑战集逐例运行，不引入并发或独立调度层。

## 已知限制

标注根据当前明确模型人工设计，非独立留出数据，也不是统计泛化评估。
只重放生产方法中的 cat 候选；基线与消融用于检测质量比较，未验证其执行收益。
初始文件内容支持 UTF-8 文本。重放仍遵循无链接、无并发修改和可信标准工具的前提。
完整字节/时间产物因运行目录与 mtime 不同不要求相同；预测及汇总必须复跑一致。

## 测试策略与关联

精确跨度、重复预测、空分母、路径拒绝、失败计数、标注回归、实际重放与独立复跑。
需求 REQ-010、REQ-011；见 [需求](../../REQUIREMENTS.md)、[实验索引](../experiments/INDEX.md)。
无新增 ADR。对外表述必须经 [CLAIMS](../../CLAIMS.md) 与 QA 审核。
